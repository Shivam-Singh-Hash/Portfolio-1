HealthCure

A comprehensive hospital management system — handling patient records, doctor schedules, appointment booking, and billing from a single Java desktop application backed by a real-time SQL database.

Role Solo Developer
Timeline 2023
Status ✓ Completed
Type Academic Project
Reading Time 4 min read
01 · Problem

Why HealthCure?

Small clinics and academic hospital labs often rely on paper records or scattered spreadsheets to manage patients, appointments, and doctors. This creates errors, data loss, and wasted time. HealthCure was built to replace that chaos with a single, reliable desktop system.

Pain Points Solved

  • Paper records get lost — patient history needs to be digital and searchable
  • Appointment scheduling done manually — double bookings happen frequently
  • No visibility into doctor availability across departments
  • Billing handled in separate spreadsheets — error-prone and slow

Target Users

  • Small clinic administrators managing daily operations
  • Receptionists booking and tracking appointments
  • Doctors needing quick access to patient history
  • Academic labs simulating hospital management workflows
02 · What It Does

Core Modules

HealthCure is built around 6 core modules, each handling a distinct part of hospital operations. Every module shares the same SQL database, so data flows seamlessly — booking an appointment automatically updates the doctor's schedule and the patient's record.

👤
Patient Management
Register, search, update patient profiles and full medical history
🩺
Doctor Directory
Manage doctors by department, specialization and availability
📅
Appointments
Book, reschedule and cancel with conflict detection
🏥
Ward / Bed
Track ward occupancy and bed assignments in real time
💊
Prescriptions
Log medications prescribed per visit, linked to patient records
🧾
Billing
Auto-generate bills from appointments and treatments
03 · Database Design

Schema & Architecture

The database was designed around normalized relational tables with foreign key constraints enforcing referential integrity. JDBC handles all communication between the Java frontend and MySQL — every CRUD operation runs through parameterized prepared statements to prevent SQL injection.

04 · Challenges & Learnings

What I learned

01
Database schema design from scratch — Designing normalized tables with proper foreign keys and avoiding redundancy was my first real exposure to relational database architecture. I learned how normalization reduces anomalies and improves query performance.
02
JDBC connection management — Managing database connections efficiently — opening, reusing, and closing them properly — taught me about connection pooling concepts and why unclosed connections cause memory leaks in long-running applications.
03
Building complex Swing UIs — Java Swing requires manual layout management. Building forms with validation, dynamic tables that update from database queries, and modal dialogs taught me how UI frameworks work at a low level before I learned React.
04
Applying MVC architecture — Separating the data layer (SQL queries via JDBC), business logic (Java classes), and presentation (Swing panels) into distinct layers made the codebase maintainable and taught me why clean architecture matters even in small projects.
